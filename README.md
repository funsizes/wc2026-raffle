# WC 2026 Raffle

SvelteKit app for tracking a World Cup 2026 raffle, plus an AWS Lambda that fetches match data from [football-data.org](https://www.football-data.org/) and writes JSON to S3.

## Prerequisites

- Node.js 22+
- [AWS SAM CLI](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html)
- Docker (for `sam local invoke`)
- AWS credentials configured locally (for deploy)

Install dependencies from the repo root:

```bash
npm install
```

## Frontend (local dev)

```bash
npm run dev
```

Open the URL Vite prints (typically `http://localhost:5173`).

Other useful scripts:

| Command | Purpose |
| --- | --- |
| `npm run build` | Production build → `build/` |
| `npm run preview` | Preview the production build |
| `npm run check` | Svelte/TypeScript checks |

The static site is deployed to GitHub Pages via `.github/workflows/deploy.yml`.

## Lambda / AWS (local build & deploy)

Infrastructure lives in `infra/template.yaml`. The Lambda handler is TypeScript source in `lambda/`, but **SAM must bundle it before invoke or deploy**. The Makefile produces `fetch-matches.js` in `.aws-sam/build/FetchMatchesFunction/`.

### One-time setup

1. Copy the SAM deploy config:

   ```bash
   cp infra/samconfig.toml.example infra/samconfig.toml
   ```

   Edit `infra/samconfig.toml` if you need different stack names, bucket names, or regions. No secrets go in this file.

2. For local Lambda testing, copy env vars:

   ```bash
   cp lambda/env.local.example.json lambda/env.local.json
   ```

   Set `FOOTBALL_DATA_API_KEY` to your football-data.org token. This file is gitignored.

### Build

Always run from the **repo root**:

```bash
npm run sam:build
```

This syncs shared types into `lambda/_shared`, then runs `sam build` against `infra/template.yaml`. Output goes to `.aws-sam/build/`.

### Deploy

Build first, then deploy the **built** template (not `infra/template.yaml`):

```bash
npm run sam:build
npm run sam:deploy
```

If you use a named AWS profile:

```bash
npm run sam:deploy -- --profile YOUR_PROFILE
```

Confirm the changeset when prompted. A successful deploy uploads a bundle on the order of ~700KB+ (the compiled `fetch-matches.js`). If you see a tiny upload (~28KB), the raw TypeScript source was packaged instead — rebuild and redeploy using `npm run sam:deploy`.

After the first deploy, set secrets in **AWS Secrets Manager**:

- **Secret name:** `wcsorteo2026/app-secrets` (or whatever you set in `AppSecretsName`)
- **Value (JSON):**

  ```json
  {
    "footballDataApiKey": "YOUR_FOOTBALL_DATA_ORG_TOKEN"
  }
  ```

  Add other sensitive values to this JSON object as needed. The Lambda reads them via `APP_SECRETS_ARN`.

### Local invoke

Requires Docker. Build first, then:

```bash
npm run sam:invoke
```

With an AWS profile (if Docker/SAM needs it for metadata):

```bash
sam local invoke FetchMatchesFunction \
  -t .aws-sam/build/template.yaml \
  --env-vars lambda/env.local.json \
  --profile YOUR_PROFILE
```

Local invoke uses `FOOTBALL_DATA_API_KEY` from `lambda/env.local.json` instead of Secrets Manager.

### Type-check Lambda code

```bash
npm run lambda:check
```

## Important: which template to use

| Task | Template |
| --- | --- |
| `sam build` | `infra/template.yaml` |
| `sam deploy` | `.aws-sam/build/template.yaml` (via `npm run sam:deploy`) |
| `sam local invoke` | `.aws-sam/build/template.yaml` (via `npm run sam:invoke`) |

Do **not** invoke or deploy with `-t infra/template.yaml` after building. That points at raw `lambda/` source (`.ts` only) and causes:

```
Runtime.ImportModuleError: Cannot find module 'fetch-matches'
```

## Stack overview

Default resource names use the `wcsorteo2026` prefix:

| Resource | Default name |
| --- | --- |
| CloudFormation stack | `wcsorteo2026` |
| S3 assets bucket | `wcsorteo2026-assets` |
| Lambda function | `wcsorteo2026-fetch-matches` |
| Schedule | every 5 minutes |
| Secrets Manager | `wcsorteo2026/app-secrets` |

See `infra/template.yaml` for CORS origins, IAM policies, and optional DynamoDB snapshot table (`CreateSnapshotsTable=false` by default).

## Project layout

```
src/              SvelteKit frontend
shared/           Types and match-slimming logic (@wc2026/shared)
lambda/           Fetch-matches Lambda (TypeScript + Makefile build)
infra/            SAM template and samconfig
.aws-sam/build/   Generated by sam build (deploy/invoke from here)
```

`npm run sync:shared` copies `shared/` → `lambda/_shared` so the Lambda bundle can resolve `@wc2026/shared` during SAM packaging.
